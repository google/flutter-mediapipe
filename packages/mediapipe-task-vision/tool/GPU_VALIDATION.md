# Face GPU reference validation

The checked-in GPU goldens were generated by Google's reference wheel (core's
`referenceWheels`, the release the family libraries were built from) for macOS
arm64 on an Apple M4 Max. GitHub's hosted macOS runner has a different graphics
environment. Comparing Google's wheel and the package on the same runner
separates host differences from wrapper regressions.

The model graphs remain unchanged. No tolerances are relaxed.
The CPU suites always use their checked-in references. Local GPU tests also use
the checked-in physical-Mac outputs unless an explicit reference directory is set.

## Independent reference generation

```sh
python3 -B packages/mediapipe-task-vision/tool/prepare_gpu_reference.py --test
```

Run from the repository root after downloading both face models. The script
creates a separate Python environment from the SHA-256-pinned reference
wheel. It generates detector IMAGE/VIDEO and landmarker IMAGE/VIDEO outputs
under `build/gpu-reference/`, then runs both complete Dart face suites.
To reuse an existing reference environment, pass `--python /path/to/bin/python`.
The generators still verify its runtime version and native library digest.

Generation checks models, photos and exact raw fixture bytes. It never rewrites
tracked goldens or facial landmark drawing connections when an output directory is supplied.
The results come only from Google's Python API, independently of the Dart task.
An unsuccessful run removes the receipt so stale output cannot be accepted.

The receipt includes:

- Exact wheel URL/SHA-256 and native library SHA-256.
- Reference file digests and GPU/Metal initialization confirmation.
- Host OS and native graphics logs.
- Measured differences between Google's same-host outputs and its checked-in
  physical-Mac outputs, grouped by boxes, scores, keypoints, landmarks,
  blendshapes and transforms.

The tests accept `MEDIAPIPE_GPU_REFERENCE_DIR` only for GPU reference files.
They validate the pinned runtime, native library, GPU delegate,
Metal confirmation and reference-file digests. Missing/corrupt files fail;
there is no fallback to a different machine's outputs. Model/input hashes,
counts, ordering, metadata and all existing numeric comparisons remain checked.

## CI coverage

The `native-tasks` job in `.github/workflows/main.yaml` generates an
independent reference on its own runner before running every package suite,
the face suites included. `official-runtime-validation` does the same for every
other served vision task, through `test_macos_references.py`. Both upload
reference JSON, the receipt and logs even when comparison fails.

Logs naming `Apple Software Renderer` describe the OpenGL context; they do not
by themselves establish whether TensorFlow Lite used Metal for inference.
The official-wheel reference generation requires
`Created TensorFlow Lite delegate for Metal.` in its logs.
There is no wrapper-level CPU retry on GPU initialization failure.

## Linux

On Linux x64 the same script installs Google's pinned reference wheel for
Linux, of the release the package's Linux library was built from. Linux has no checked-in GPU goldens, so its
GPU suites run only when `MEDIAPIPE_GPU_REFERENCE_DIR` points at same-host
references. The receipt must record `gl_confirmed`: every generator log must show
an OpenGL ES context. The tasks set `use_advanced_gpu_api`, so TensorFlow Lite
runs on OpenGL ES directly and logs no delegate line.

Hosted runners only have Mesa's llvmpipe, which Google's runtime refuses by name
(`GPU emulation detected`). The `linux-gpu` job in `.github/workflows/desktop.yaml`
sets Mesa's `force_gl_renderer` to rename the same software renderer, plus
`EGL_PLATFORM=surfaceless` because the runner has no display. The receipt
records the override as `renderer_override`. The job then runs the face suite's
refusal test without the rename, which must fail with `gpuUnavailable` and never
fall back to CPU. A physical GPU needs no override; the script for that run,
`test_linux_gpu.sh`, is in git history at `9383185`.

This validates equivalence to the official task on the tested host. It is not a
claim of bit-identical GPU output across hardware/drivers, universal model
accuracy, or physical-Mac GPU performance on a hosted runner.
